01The problem

Resistance can now be predicted from a bacterial genome, but a prediction is only as good as the record behind it. The reference database is updated regularly, tools change their output, and input files get downloaded again. Months later it is often impossible to say which version of what produced a given result.

So the record had to be part of the result: written by the workflow itself, for every sample, whether the call worked or not.

02The workflow

For each sample the workflow keeps AMRFinderPlus's own report untouched and writes a provenance record beside it: the caller version, the full command, the SHA-256 of the input, the SHA-256 of every database file and a digest over all of them, the thresholds, the status, and the hash of the report. A harmonise step then turns the report into a fixed 24-column table that keeps every original column.

03Decisions and trade-offs

A record even for failures

The provenance record is written whether the call succeeds or fails, so a failed sample leaves evidence of what was tried, not a gap.

Never fetch a database at run time

The workflow refuses to download or update its reference database. A separate script fetches a named release and writes a checksum list and a provenance file beside it.

All or nothing per sample

Harmonising stops on a hash mismatch, a missing or duplicate header, or a malformed row. Rows are buffered, so a bad row cannot leave a half-written file.

Retry only what is worth retrying

Exit codes that mean the scheduler ran out of memory or time are retried up to twice with more of both. Anything else stops the run, so a real error is never hidden by a retry.

04At scale, and on a second platform

AMRScan is the data layer for a study of whether resistance predicted from a genome holds up on lineages, countries and years that were not in training. The cohort is 10,521 public E. coli genomes with 162,701 susceptibility results from 26 countries, collected from 2009 to 2025. Every result can be traced to the export file, row and download it came from.

  • All 10,521 genomes were called through the same wrapper on a workstation: 10,521 succeeded, none failed, and no provenance check failed. The run was interrupted once. Earlier calls were checked again before they were reused, and 22 partial outputs were set aside and redone.
  • 1,000 of them, picked at random, were then run through Nextflow on NCI Gadi under PBS Pro: 2,000 tasks, all finished on the first attempt, in 1 hour 10 minutes of wall time and about 27 service units. Every input hash matched, and every raw report was byte-identical to the earlier run on the other machine.
  • The fingerprint caught something a release name would not. Between the two downloads NCBI had added five files to the same database release, so the database digests differ and the harmonised tables, which carry that digest, are not identical. The raw results are.
