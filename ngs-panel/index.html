Case study · open source

Germline NGS panel validation

Before a clinical laboratory reports variants from a sequencing pipeline, it has to show that the pipeline finds what is there and reports nothing that is not. I carried out that validation in the open, end to end, and wrote it up the way a diagnostic laboratory would.

Code and reports on GitHubProject page

My role
Sole author: pipeline, validation plan, reports and risk register
Pipeline
Nextflow DSL2, BWA-MEM, GATK HaplotypeCaller with hard filters, RTG vcfeval, in Docker or Apptainer
Truth data
Five Genome in a Bottle reference genomes (HG001 to HG005), 31 genes from PanelApp Australia
Standards
Written with reference to AMP/CAP, NPAAC and ISO 15189:2022. This is not an accredited laboratory, and the repository says so.

01The bar, set first

The pipeline looks for inherited variants in 31 genes linked to breast, ovarian and colorectal cancer, including BRCA1, BRCA2, PALB2, the mismatch repair genes, APC and TP53. Genome in a Bottle samples are the test: their true variants are known from many sequencing technologies, so every call can be scored as right, missed or false.

The acceptance criteria were written into a config file before the pipeline existed, and the git history shows it: the criteria were committed before the first pipeline code, and later edits changed only comments.

  • SNV sensitivity and precision at least 0.99; indel sensitivity and precision at least 0.95; genotype concordance at least 0.99.
  • At least 98% of panel bases covered 20 times or more, after duplicates and low-quality reads are removed.
  • Two runs of the same data must give identical records, and two libraries from the same person must agree on 99% of genotypes.
  • Under change control, no metric may drop by more than 0.005, and every call that changes in the panel must be reviewed.

02The pipeline

Every tool version is pinned, and the container is built from an explicit lock file. The filters are GATK's published hard-filter thresholds, not tuned to the test data.

03The first version failed

On the first reference sample the pipeline missed 3 of 53 panel SNVs in one library and 2 of 53 in the other. All three misses in the first library had been called correctly and then removed by a single strand-bias rule in the standard filter. Across the exome, that one rule alone removed 2,796 correct SNVs.

  • The fix went through change control. A written plan named the candidate filters and the rule for choosing between them before any candidate was run.
  • Candidates were compared on odd-numbered chromosomes, outside the panel. The chosen filter was then tested on even-numbered chromosomes, so the test data played no part in the choice.
  • On the test half, SNV sensitivity rose from 0.847 to 0.906 in one library and from 0.852 to 0.912 in the other, while precision fell by no more than 0.0017.
  • The report accepted the change and said plainly that this was not a claim that the new version met all the criteria.

04Checked on data it had never seen

Four more reference genomes, sequenced by a second laboratory with a different capture kit, were run from alignment. Across all five genomes no panel SNV was missed: 316 of 316. The results are reported with their weak points:

  • The 316 are only 116 distinct variants, so the pooled confidence interval is optimistic.
  • Panel precision was 316 of 320, 0.988, just below the 0.99 bar. All four false calls were the same pair of positions in PMS2, in two genomes.
  • There were too few indels in the panel (5 distinct) to judge indel accuracy, and the report says so rather than quoting a number.

05Running it like a laboratory

A risk register

18 failure modes, each scored for severity, likelihood and how easily it would be caught, with actions recorded. The two highest are variant types outside the validated scope and variant descriptions (HGVS) that were never validated.

A supplier update, checked from outputs

A DeepVariant upgrade was assessed from the exported VCFs alone, as a laboratory would with software it cannot inspect. 595 of 101,297 records changed only in their filter label, a change the release notes did not mention, and no call changed.

Repeatable to the byte

The same data run twice gave 102,862 records each time, none different, with the same checksum. Each DeepVariant version was also run twice on different machines with no difference.

Honest about the gaps

The review that a second person would do in a laboratory was done by me alone, and the repository maps the ISO 15189 and NPAAC requirements to what was and was not possible outside an accredited laboratory.
